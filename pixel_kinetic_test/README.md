## 一键重建

需要 `python3`（含 numpy、pillow、scipy）和带 libx264 的 `ffmpeg`：

```bash
./build.sh
```

在 4 核 CPU、无 GPU 的环境下，渲染全片约 20 秒，音频合成约 3 秒。

## 渲染原理

1. 每帧先在 **270×480** 的低分辨率画布上绘制。
2. 交给 FFmpeg 用**最近邻**整数放大 4 倍到 1080×1920。每个像素都是严格的 4×4 方块，色度采样不会糊边。
3. 镜头特写用整数 2 倍放大，同样保持像素块整齐。
4. 画面、HUD 和音频都从 `src/timeline.py` 读取同一份时间表：
   - **节拍表**：120 BPM 起，16 秒后提速到 150 BPM。
   - **撞击时间**：5 次撞击都落在小节第一拍。
   - **世界时钟**：用来实现顿帧和慢动作。
5. 角色动画按「世界时间」计算，所以顿帧和慢动作对所有物体一致生效。闪白、震屏、HUD 和音乐按真实时间走。

## 自查记录（制作中发现并修复的问题）

**数值与文字**
- 第 5 关算式和屏幕数字对不上（3,014 J 与 ½×125×6.94² = 3,010 J），统一改为 6.94 m/s。
- 倍数原先用「四舍六入五成双」，544.5 显示成了 ×544，改为四舍五入，显示 ×545。
- 字库缺「然」「≈」两字，改了文案，并加入渲染前的缺字检查。
- 印章旋转后点阵中文被扭坏（「测」字无法辨认），改为水平印章，文字保持清晰。

**节奏与镜头**
- 第 3 关算式还没打完就切进了慢动作，撞击前看不到完整数据。加快该关卡片节奏，保证每关撞击前都完整显示质量、速度、动能。
- 手机碎屏特写被 HUD 挤满，特写期间改为只留顶部精简条。
- 拟声字（啵、嘭!）原先固定在屏幕某处，改为按真实撞击点换算坐标。
- 车铃气泡在电动车入画时被切出画面，延后出现并限制在画面内。

**画面连续性**
- 电动车停在行人回落的位置后凭空消失，改为骑手停稳后骑车离开。
- 保龄球在第 5 关警报开始时凭空消失，提高反弹速度，让它提前滚出画面。
- 震屏时镜头越过图层边界，露出一行错误颜色，给天空层和街道层都加了余量。
- 结尾结论卡用的是冻结时间，所以一直不出现；改为使用真实时间。

**平台适配**
- 顶部卡片下移、动能大字移到左侧、结尾免责声明上移，避开抖音和 TikTok 的标签栏、右侧按钮列和底部文案区。
- 第一帧原本只有星空，平台默认封面会很弱，改为 0.1 秒起出标题；另外单独设计了封面图。

**声音**
- 撞击声被音乐盖住、升级感不足，加入侧链压缩，并逐关加重低频。
- AAC 编码后真峰值超过 -1 dBTP，改为真峰值限幅到 -2 dBTP，编码后实测 -1.6 dBTP。
- 音乐硬切处有数字咔哒声的风险，加入 4 ms 微淡出。

**验证结果**
- 4 次大撞击的音频瞬态都在画面撞击帧之后 3 到 4 ms，A/V 同步误差远小于一帧。
- 最终成片（CRF 10）解码帧与原始渲染帧对比，PSNR 为 43.6 到 46.8 dB，视觉上无损，平台二次压缩也有余量。

## 说明

本片为虚构像素动画。所有数值只用于动画演示，不代表任何人体伤害阈值。片中没有血液、伤口或写实受伤，受击表现全部是街机式的夸张反馈。
